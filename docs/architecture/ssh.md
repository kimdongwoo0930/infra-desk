# ssh: 서버에 SSH로 들어가는 계층

[← 개요](README.md)

## 왜 있나

터미널, SFTP, Docker 관리, 실시간 모니터링은 모두 "서버에 SSH로 로그인해서 뭔가 하기"다. 이 일은 **서버가 Oracle에 있든 집에 있든 똑같다.** 그래서 `ssh`는 클라우드(`core.CloudProvider`)와 완전히 분리되어 있고, 다른 `com.infradesk` 모듈을 아무것도 import하지 않는다.

> `provider/ssh`와 헷갈리지 말 것. 그쪽은 포트가 열려 있는지만 확인하는 상태 표시용이다 → [개요](README.md#헷갈리기-쉬운-것-ssh가-두-개다)

## 구조: 인터페이스 + 구현

```
ShellConnector (인터페이스)           ShellSession (열린 연결)
 └─ MinaShellConnector                 └─ MINA SSHD 채널
```

`ShellConnector`가 SSH 연결의 입구다. 네 가지를 할 수 있다.

| 메서드 | 하는 일 | 쓰는 곳 |
|---|---|---|
| `open(target, prompt, cols, rows)` | PTY가 있는 **대화형 셸** | 터미널 탭 |
| `open(..., command)` | 같은 PTY로 **명령 하나**를 실행(`docker exec -it`) | 컨테이너 셸 탭 |
| `exec(target, prompt, command)` | PTY 없이 명령을 실행하고 출력 읽기 | 일괄 실행, 컨테이너 목록, 실시간 모니터링 |
| `sftp(target, prompt)` | 파일 목록·전송·폴더 만들기·이름 바꾸기·권한·삭제 (`RemoteFiles`) | SFTP 창 |

`service.TerminalService`가 이 인터페이스를 쓰고, 어떤 구현을 쓸지는 `app`이 정한다.

## 접속 흐름 (`MinaShellConnector`)

```
SshTarget(호스트, 포트, 사용자, 개인키)
   │
   ├─ 1. TCP 연결
   ├─ 2. 호스트 키 확인
   │      known_hosts에 있다 → 일치하면 통과, 다르면 거부(HOST_KEY_CHANGED)
   │      처음 본다         → HostKeyPrompt로 사용자에게 묻고, 신뢰하면 known_hosts에 저장
   ├─ 3. 공개키 인증 (개인키, 있으면 암호도)
   └─ 4. 셸 채널 열기 (PTY xterm-256color)
```

`HostKeyPrompt`는 "이 서버 지문을 신뢰할까요?"를 묻는 **콜백 인터페이스**다. `ssh`는 화면을 모르기 때문에 질문을 UI에 위임한다(실제 구현은 `ui.terminal.HostKeyDialog`). 어느 스레드에서든 호출될 수 있다.

실패는 `SshException`으로 올라온다. 종류(`CONNECT`, `AUTH`, `KEY_FORMAT`, `HOST_KEY_REJECTED`, `HOST_KEY_CHANGED`)와 사용자에게 보여줄 한국어 메시지가 담겨 있다.

## 접속 풀 (`SessionPool`)

접속(TCP + 인증)은 서버의 인증 로그에 남고 시간도 걸린다. 그래서 명령마다 새로 접속하지 않고, **서버와 목적마다 SSH 연결 하나를 유지하면서 그 위에서 채널만 열어** 쓴다.

### 목적(`Purpose`)별 연결

| 목적 | 쓰는 곳 | 유휴 종료 | 연결이 죽어 있었을 때 |
|---|---|---|---|
| `QUERY` | 측정, 서버 정보, 컨테이너 목록·로그, 실시간 모드(2초 스트림) | 15분 | **한 번** 새로 맺어 다시 시도 |
| `COMMAND` | 일괄 실행, 컨테이너 시작·정지 | 5분 | **다시 시도하지 않는다** |
| `FILES` | SFTP 폴더 탐색과 파일 작업 | 5분 | 다시 시도하지 않는다 |
| `TRANSFER` | SFTP 전송 대기열 | 5분 | 다시 시도하지 않는다 |

- **목적마다 연결을 나누는 이유:** 한 TCP 연결 위에서 큰 전송이 대역폭을 채우면 같은 연결의 조회도 느려진다.
- **COMMAND는 자동 재시도를 하지 않는다.** 응답만 못 받았을 뿐 서버에서 이미 실행됐을 수 있어서, 다시 시도하면 같은 명령이 두 번 실행될 수 있다. 목적을 밝히지 않은 `exec`도 COMMAND로 취급한다.
- **재시도는 "재사용하던 연결이 죽어 있었을 때"만 한다.** 새로 맺은 연결에서 난 실패는 다시 시도하지 않는다(인증 실패가 서버 로그에 두 배로 쌓이지 않게).
- **터미널 탭은 풀 밖이다.** 사용자가 열고 닫는 연결이라 탭마다 따로 맺고, 닫으면 연결째 닫힌다.

### 채널과 연결의 `close()`
`ShellSession.close()`와 `RemoteFiles.close()`는 **채널만 닫고 연결은 풀에 돌려준다.** 풀에서 빌린 연결(`SessionLease`)을 돌려주는 것이고, 풀 밖에서 맺은 터미널 연결은 돌려주면 닫는다. 같은 목적의 SFTP 두 개는 연결 하나 위의 채널 둘이다.

### 연결을 오래 두는 만큼 지키는 규칙

| 규칙 | 내용 |
|---|---|
| 수명 12시간 | 한 키로 인증된 연결을 너무 오래 두지 않는다. 12시간이 지나면 **쓰는 곳이 없는 빈틈에** 닫고 다음에 새로 맺는다(그때 키를 보관소에서 다시 읽는다). QUERY는 빈틈이 10분 동안 안 생기면 강제로 닫는다. 전송 등 다른 목적은 쓰는 중이면 끝날 때까지 기다린다 |
| 설정이 바뀌면 즉시 끊김 | SSH 설정을 저장하거나 서버를 지우면 그 서버의 연결을 바로 닫는다. 사용자 이름·키·주소가 달라진 채로 요청이 오면 옛 연결을 버리고 새로 맺는다 |
| 창이 메뉴 막대로 숨음 | X로 닫아 메뉴 막대에만 있을 때는 **조회(QUERY) 연결만 남긴다.** 쓰고 있지 않은 다른 연결은 바로 닫고, 쓰는 중인 연결(전송 중 등)은 끝나는 대로 닫는다. 다시 나타나면 되돌린다. Dock으로 최소화(iconify)하는 것과는 다른 상태다 |
| 끊어진 연결 감지 | 풀 연결은 30초마다 heartbeat(`keepalive@openssh.com`)를 보내고, 응답이 2번 연속 없으면 연결이 죽은 것으로 보고 닫는다(약 1~1.5분 안에 감지). 노트북이 잠들었다 깨어나도 죽은 연결을 오래 붙들지 않는다 |
| 개인키를 풀에 남기지 않음 | 풀은 키가 바뀌었는지 알아볼 해시만 보관한다 |

- **heartbeat 때문에 `SshClient`가 둘이다.** MINA는 heartbeat 설정을 세션이 만들어질 때 읽어 가서 세션마다 켜고 끌 수 없다(세션 생성자에서 이미 서비스가 만들어진다). 그래서 풀 연결용(heartbeat 켬)과 터미널용(켜지 않음) 클라이언트를 따로 둔다.
- 풀은 30초마다 스스로 정리한다(죽은 연결, 유휴 연결, 수명이 다한 연결).
- **접속을 시도해도 되는지**는 풀이 아니라 [`SamplingGate`](service.md#자동-ssh-접속-규칙-samplinggate)가 정한다(실패하면 멈춤·대기, 창이 숨으면 5분에 한 번). 이미 열린 연결 위에서 채널을 여는 것은 가벼워서 풀은 간격을 제한하지 않는다.

## 클래스 안내

### 접속 정보와 설정

| 클래스 | 역할 |
|---|---|
| `SshTarget` | 어디에 어떻게 연결할지(호스트, 포트, 사용자, 개인키, 암호). 개인키는 연결하는 동안만 메모리에 두고 로그에 남기지 않는다 |
| `SshSettings` | 서버 하나의 비밀이 아닌 설정(서버 id, 사용자, 포트). 개인키는 `storage`의 금고에 있다 |
| `SshConfig` | `~/.ssh/config`를 읽어 공인 IP → Host → 사용자·포트·키 파일을 추천한다 |
| `SavedCommand` | 터미널 사이드 패널의 "저장된 명령어" 버튼 하나 |

### 연결과 실행

| 클래스 | 역할 |
|---|---|
| `ShellConnector`, `ShellSession` | 위에서 설명한 입구와 열린 연결 (입출력 스트림, 창 크기 조정, 종료 대기) |
| `Purpose`, `SessionPool` | 접속 목적과 연결 재사용 풀(위 "접속 풀") |
| `ExecResult` | 명령 실행 결과(종료 코드, 출력, 실패 메시지) |
| `HostKeyPrompt` | 처음 보는 호스트 키 확인 콜백 |
| `SshException` | 종류별 SSH 실패 |

### 서버에서 읽어 오는 것

| 클래스 | 역할 |
|---|---|
| `HostFacts` | SSH 한 번으로 업타임·OS·루트 디스크·열린 포트 읽기 (서버 상세의 정보 칸) |
| `ProcStats` | 원격 `/proc` 스냅샷 명령, 파싱, 두 스냅샷 사이 사용률 계산 (실시간 모드) |
| `DockerCommands`, `Container` | SSH로 실행할 Docker 명령(컨테이너 ID는 16진수만 허용)과 결과 파싱. `docker exec -it`로 컨테이너 셸·DB 콘솔도 연다 |
| `RemoteFiles`, `RemoteFile`, `Transfers` | SFTP 작업: 목록·`stat`, 업로드·다운로드(오프셋을 주면 이어받기·이어올리기, 진행률 콜백이 예외를 던지면 취소), `mkdir`, `createFile`(빈 파일, 같은 이름이 있으면 덮어쓰지 않고 실패), `rename`, `chmod`, 삭제. `deleteRecursively`는 폴더를 통째로 지우되 **심볼릭 링크는 따라가지 않고 링크만 지운다**. `RemoteFile`은 권한(`rwxr-xr-x`)과 링크 여부를 가진다 |
| `TransferQueue` | 파일·폴더 전송 대기열(아래) |
| `LocalFiles` | 이 컴퓨터의 폴더 목록·새 폴더·새 파일·이름 바꾸기·삭제(SFTP 창의 왼쪽 패널). 서버 쪽과 같은 표를 쓰도록 항목을 `RemoteFile` 모양으로 돌려준다. OS의 경로 표기를 그대로 쓰고, 삭제는 가능하면 휴지통으로 보낸다 |

## 전송 대기열 (`TransferQueue`)

SFTP 창의 업로드·다운로드는 모두 이 대기열을 거친다. 작업(파일 하나 또는 폴더 통째)을 **하나씩 차례로** 실행한다.

- **별도 연결:** 폴더를 둘러보는 연결과 따로 SFTP 연결을 맺는다(첫 작업이 실행될 때). 전송 중에도 화면이 멈추지 않고 폴더를 탐색할 수 있다.
- **임시 이름으로 쓰고 끝나면 바꾼다:** 파일은 `이름.infradesk-part`로 쓰다가 완료되면 제 이름으로 바꾼다. 끊긴 파일이 완성본처럼 보이지 않는다.
- **취소·실패·이어받기:** 취소하거나 실패해도 임시 파일은 남는다. `retry`하면 끝난 파일은 건너뛰고 중단된 파일은 이어서 전송한다. 이때 **원본의 크기·수정 시각이 처음과 같을 때만** 이어받는다(받기는 서버에서 `stat`으로 현재 상태를 다시 읽는다). 달라졌으면 처음부터 전송해서 낡은 조각이 섞이지 않는다. 작업을 목록에서 지우면 남은 임시 파일도 정리한다. 이어받기는 앱을 켜 둔 동안만 된다.
- **권한은 확인한 뒤에 정한다.** 업로드는 권한을 이렇게 다룬다.
  - **덮어쓰기:** 기존 서버 파일의 권한을 **먼저 읽어서 그대로 유지**한다(600인 `.env`가 644가 되거나 실행 권한이 사라지지 않게). 서버 기본값으로 만들면 권한이 사라지는 것이 실제로 확인됐다.
  - **새 파일:** **내 컴퓨터 파일의 권한**을 따른다(600 키는 600, 755 스크립트는 755). Windows처럼 POSIX 권한이 없으면 서버 기본값이다. 새로 만든 폴더도 내 컴퓨터 폴더의 권한을 받는데, 안에 파일을 다 올린 **뒤에** 적용한다(읽기 전용 폴더에 파일을 못 올리는 일이 없게).
  - **임시 파일은 내용을 올리기 전에 최종 권한부터 맞춘다.** 비어 있는 임시 파일을 만들고 `chmod`한 다음 내용을 올려서, 비밀 파일이 잠깐이라도 넓은 권한으로 서버에 놓이는 순간이 없다. 권한을 맞추지 못하면 **내용을 올리지 않고 실패**한다(넓은 권한으로 올라가는 것보다 낫다).
  - **이름을 바꾼 뒤 서버에서 다시 읽어 확인한다.** 다르면 한 번 바로잡아 보고, 그래도 다르면 실패로 알린다.
  - **서버가 권한을 알려주지 않으면**(SFTP 속성에 권한 플래그가 없음) 값이 0으로 읽혀 `chmod 000`이 되는 일이 없도록 "알 수 없음(-1)"으로 취급하고 건드리지 않는다. 이때는 완료 메시지에 알린다.
  - **소유자는 되돌릴 수 없다.** 일반 계정은 `chown`을 못 해서, 다른 사용자 소유 파일을 덮어쓰면 소유자가 이 계정으로 바뀐다. 이를 기록했다가 **전송 하나가 끝나면 한 번만** 알린다(폴더 안의 여러 파일은 모아서). 소유자는 SFTP가 번호(uid)로만 주므로, 임시 파일(우리가 만든 것)의 uid와 비교한다.
  - 서버 파일 편집의 저장도 같은 업로드 경로를 쓰므로 똑같이 적용된다.
- **덮어쓰기 정책:** 작업마다 `overwrite`를 받는다. `false`면 같은 이름의 파일을 건너뛰고, `true`면 임시 이름으로 다 올린 뒤 기존 파일을 지우고 이름을 바꾼다.
- **심볼릭 링크:** 폴더를 통째로 전송할 때 링크는 따라가지 않고 건너뛴다(순환·엉뚱한 파일 방지). 건너뛴 수는 완료 메시지에 나온다.
- 리스너는 작업 스레드에서 불리고, 진행률은 0.1초에 한 번만 알린다. 화면은 EDT로 넘겨서 갱신한다.

## 보안 규칙

- Docker TCP 포트(2375)는 절대 열지 않는다. 모든 Docker 작업은 SSH 안에서 `docker` 명령으로 한다.
- 개인키·암호는 로그에 남기지 않는다.
- 호스트 키가 바뀌면 연결을 거부한다.
