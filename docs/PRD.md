# PRD: infra-desk

## 1. 배경과 문제

- 여러 클라우드 계정에 서버가 흩어져 있어, 상태 확인과 제어를 하려면 계정마다 콘솔에 로그인해야 한다.
- 서버에 접속하려면 별도의 SSH 클라이언트를, 파일을 옮기려면 별도의 SFTP 클라이언트를, 컨테이너를 보려면 다시 터미널을 열어야 한다.
- 맥미니, 집 서버처럼 클라우드가 아닌 서버는 어느 콘솔에도 나오지 않는다.
- 대규모 관제 도구(Grafana, Prometheus 등)는 개인·소규모 서버 운영에는 과하고 설정이 번거롭다.

## 2. 목표와 비목표

### 목표
- 여러 클라우드 계정과 직접 연결한 서버를 **한 화면**에서 확인하고 제어한다.
- 서버에 아무것도 설치하지 않고 SSH 연결만으로 모니터링, 터미널, 파일, Docker를 다룬다.
- macOS(Apple Silicon)와 Windows에서 동일하게 동작한다.

### 비목표
- 대규모 서비스 운영(수십 대 이상 서버, 팀 협업, 권한 분리)은 대상이 아니다.
- 서버에 에이전트를 설치하는 방식의 상시 수집은 하지 않는다.

## 3. 대상 사용자

- 여러 클라우드 계정과 개인 서버를 혼자 운영하는 개인 개발자.

## 4. 핵심 기능

| 기능 | 설명 |
|---|---|
| 계정 등록 | 계정별 인증 정보(tenancy OCID, user OCID, fingerprint, region, API 개인키)를 등록한다 |
| 직접 연결 서버 | 클라우드가 아닌 서버를 주소와 SSH 키만으로 추가한다 (Linux·macOS) |
| 서버 목록·상태 | 모든 계정의 서버를 모아 상태(RUNNING, STOPPED 등)를 표시한다 |
| 서버 제어 | 시작, 정지, 재부팅. 변경 작업은 확인 다이얼로그를 거친다 |
| 상태 자동 새로고침 | 폴링으로 상태를 갱신한다 |
| 모니터링 | CPU, 메모리, 네트워크 그래프. 실시간 모드(SSH)를 지원한다 |
| 서버 정보 | 업타임, OS, 디스크 사용량, 열린 포트 |
| SSH 터미널 | 앱 안에서 서버별 탭으로 접속한다 |
| SFTP | 파일 탐색, 업로드·다운로드(이어받기), 편집, 이동, 삭제, 권한 변경 |
| Docker | 컨테이너 목록·상태·사용량, 로그, 시작·정지·재시작, 컨테이너 안 셸과 DB 콘솔 (SSH로만) |
| 편의 기능 | 저장된 명령어 버튼, 메뉴 막대 아이콘, 앱 안 업데이트 |
| 디스코드 알림 | 서버 비정상 정지, 계정 연결 끊김, CPU 고사용 알림 (준비 중) |
| 데모 모드 | 실제 키 없이 가짜 데이터로 모든 화면을 둘러본다 |
| 패키징 | macOS `.dmg`, Windows `.zip` 배포 |

## 5. 요구사항

### 기능 요구사항
- 계정은 `provider`(ORACLE, AWS, ...) 값을 가지며, 이 값으로 클라우드 구현체가 결정된다.
- 클라우드별 상태 문자열은 공통 상태(RUNNING, STOPPED, STARTING, STOPPING, UNKNOWN 등)로 정규화해서 보여준다.
- SSH 키는 서버마다 등록한다. 같은 키를 여러 서버에 써도 된다.
- 서버 접속은 SSH만 쓴다. Docker TCP 포트(2375)는 쓰지 않는다.

### 조회 주기
| 대상 | 주기 |
|---|---|
| 서버 상태 | 30~60초 폴링. 시작/정지 직후에는 상태가 안정될 때까지 5초 간격 |
| 메트릭 (OCI) | OCI Monitoring 1분 간격 (OCI가 1분 단위로 집계) |
| 메트릭 (직접 연결 서버) | SSH로 1분마다 읽는다 |
| 실시간 모드 | 서버 상세 화면을 볼 때만, SSH로 `/proc/stat`, `/proc/meminfo`를 2~5초마다 읽는다 |
| 컨테이너 목록 | 주기적으로 계속 읽지 않는다. 서버를 고를 때(30초 안에 다시 고르면 저장된 값), 서버 상태가 바뀔 때, 새로고침을 누르거나 컨테이너 동작을 한 뒤에 SSH로 `docker ps`·`docker stats`를 읽는다 |
| 컨테이너 로그 자동 새로고침 | 기본은 꺼짐. 사용자가 켠 동안, 컨테이너 탭이 보일 때만, 실행 중인 컨테이너의 `docker logs --tail`을 10초마다 다시 읽는다(조회용 연결을 재사용하고, 이미 읽는 중이면 건너뛴다). 읽기에 실패하면 스스로 꺼진다 |

OCI API 요청 제한을 고려해 과도한 폴링은 하지 않는다.

### 비기능 요구사항
- **보안**: 비밀값(API 개인키, SSH 키, 웹훅)은 `secrets.vault`에 AES-256-GCM으로 암호화해 저장하고, 암호화 키는 OS 키체인에만 둔다. 평문 저장과 로그 출력은 하지 않는다. 공인 IP는 화면에서 기본으로 가린다.
- **안전**: 정지, 재부팅 같은 변경 작업은 실행 전에 확인을 받는다.
- **반응성**: 네트워크 호출 때문에 UI가 멈추지 않는다.
- **SSH 연결**: 서버당 목적별(조회 QUERY, 명령 COMMAND, 파일 FILES, 전송 TRANSFER) 연결을 하나씩 유지하고 그 위에서 채널을 열어, 호출마다 새로 접속하지 않는다. 터미널 탭은 풀 밖에서 따로 열고 닫는다. 연결은 12시간이 지나면 쓰는 곳이 없는 빈틈에 새로 맺고, 설정이 바뀌면 즉시 끊고, 유휴이면 닫는다. 창이 메뉴 막대로 숨으면 조회 연결만 남긴다. 상세는 `docs/architecture/ssh.md`.
- **호환성**: macOS(Apple Silicon)와 Windows 모두 지원한다.

## 6. 현재 상태

- 구현됨: 위 "핵심 기능" 표의 항목 중 디스코드 알림을 제외한 전부. OCI만 지원한다.
- 확인 상태: Ubuntu에서 실사용 확인, 나머지 배포판과 Windows Server는 부분 확인 (자세한 표는 README의 호환성).
- 진행 중·계획: 노션 「아이디어」 페이지를 따른다. 주요 항목은 SFTP 안전장치, 로그·트래픽 탭. (SSH 세션 풀은 구현됨)

## 7. 이후 확장

- **다른 클라우드**: `AwsProvider`, GCP 등
- **로그·트래픽 조회**: `LogSource` 추상화로 SSH 직접 조회와 Loki 연동
- **AI 에이전트**: 로컬 LLM(Ollama 등)이 SSH 명령을 제안하고 사용자가 허용/거절한다. 읽기 전용 모드와 감사 로그를 함께 둔다.
