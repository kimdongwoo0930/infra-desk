# 디자인 v2에서 지금 기능이 없는 부분

`DESIGN-v2.md`의 시안을 지금 코드와 맞춰 보고, **화면에는 나오지만 뒤에서 받쳐 주는 기능이 없는 것**을 모았다.
이 문서가 "무엇을 어떻게 다룰지"의 기준이다. 구현하면서 상태가 바뀌면 이 표를 고친다.

## 다루는 방법 세 가지

| 표시 | 뜻 | 화면에서는 |
|---|---|---|
| **재배치** | 기능은 이미 있고, 새 화면 구조로 옮기기만 하면 된다 | 그대로 동작한다 |
| **준비 중** | 기능이 아직 없다. 자리만 만들어 둔다 | 흐리게 보이고, **눌러도 아무 일도 하지 않는다.** 마우스를 올리면 "준비 중이에요" 안내가 뜬다 |
| **보류** | 이번 작업 범위 밖이다 (에이전트) | 화면에 넣지 않는다 |

### "준비 중"의 규칙

- **동작하는 척하지 않는다.** 특히 안전과 관련된 것(읽기 전용 스위치)이 켜진 것처럼 보이는데 실제로는 막지 못하면 위험하다. 그래서 준비 중인 스위치는 **켤 수 없게** 막는다.
- 준비 중 표시는 부품 하나(`ComingSoon` 같은 이름)로 만들어 모든 곳에서 같은 모습으로 쓴다. 기능을 만들 때 이 부품만 걷어내면 된다.
- 준비 중인 자리가 코드에서 눈에 띄도록 주석에 `// 준비 중(v2):`를 붙인다. 나중에 `grep`으로 한 번에 찾는다.

## 6. 에이전트 (이번에는 만들지 않는다)

`AgentDock`(패널), `AgentCases`(승인 카드 9가지), 설정의 에이전트 항목, 타이틀바 [에이전트 ⌘J] 전부 **보류**다.
화면에 흔적을 남기지 않는다. 명령 분류, 허용 흐름, 출력 자르기·가리기, 모델 연결은 별도 설계 뒤에 한다.

## 먼저 상의해야 하는 것 (코드를 쓰기 전에)

각각 보안이나 SSH 접속 수에 영향을 주므로 구현 전에 사용자와 정한다.

1. **읽기 전용 모드**: 무엇을 막는지, 어디에 저장하는지 (앱 재시작 후에도 유지할지).
2. **활동 기록 저장소**: 파일 형식, 30일 삭제 방식, 무엇을 남기고 무엇을 남기지 않는지.
3. **개요의 디스크 조회**: 간격(5분 이상), 조회용 연결(QUERY)을 쓰는 방식, 정지된 서버 건너뛰기.
4. **`SavedCommand` 범위 필드**: 기존 `commands.json`과 호환(필드가 없으면 "모든 서버").
5. **`SessionPool`이 열린 연결을 읽어 주는 방법**: 상태 막대와 설정 표가 쓴다.
6. **시안의 PNG가 없다**: `images/`에 이미지가 없어서 겉모습 비교는 `dc.html`의 수치로만 한다. 이미지를 넣으면 `./gradlew snapshot`과 눈으로 비교할 수 있다.
