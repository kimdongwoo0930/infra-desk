# 디자인 v2 (개편안)

v1(`docs/design/DESIGN.md`)을 바탕으로 한 개편안이다. 색이나 크기가 v1과 다르면 **v2를 따른다**.
HTML 시안을 앱에 넣는 게 아니다. 시안을 보고 Swing + FlatLaf로 최대한 비슷하게 만든다.

## 이 폴더

```
docs/design/v2/
  DESIGN-v2.md          이 문서
  screens/*.dc.html     화면별 시안 원본 (아래 "시안 읽는 법")
  images/*.png          화면별 이미지 (캔버스에서 내보낸 것)
```

### 시안 읽는 법 (`*.dc.html`)
- 브라우저로 바로 열리지는 않는다(디자인 캔버스 전용 런타임이 필요하다). **텍스트로 읽는다.**
- 배치·색·크기는 각 요소의 `style="…"`에 그대로 적혀 있다.
- `{{이름}}`은 빈칸이다. 파일 맨 아래 `<script>`의 `renderVals()`가 돌려주는 값으로 채워진다. 목록(`<sc-for>`)의 데이터와 상태별 스타일도 거기에 있다. 데모 데이터를 만들 때 그 값을 그대로 쓴다.
- `<sc-if value="{{x}}">`는 조건부 표시, `<sc-for list="{{xs}}" as="x">`는 반복이다.
- 화면 사이 이동은 `<a href="다른화면.dc.html">`로 적혀 있다.
- 겉모습은 이미지(`images/`)가 기준이고, 정확한 수치는 `dc.html`에서 읽는다.

## 글꼴·크기·간격

- UI: 지금 `Theme`의 기본 글꼴을 그대로 쓴다 (시안은 IBM Plex Sans KR로 그림). 고정폭: `Theme.monoFont` (시안은 JetBrains Mono).
- 크기: 본문 13, 보조 12–12.5, 캡션 11.5, 카드 제목 13.5–14 굵게, 섹션 제목 18 굵게, 화면 제목 22 굵게, 큰 숫자 20–24 굵게.
- 숫자는 자릿수 폭을 맞춘다 (표·지표·시각).
- 모서리: 버튼·입력 6, 카드 8, 다이얼로그·빠른 실행 12, 칩 14(알약), 배지 9–10.
- 높이: 타이틀바 44, 상태 막대 26, 사이드바 폭 240, 화면 머리 버튼 34, 도구 막대 버튼 28–32, 사이드바 서버 행 30, 표 행 약 40.
- 간격: 화면 안쪽 여백 좌우 28, 카드 사이 12–20, 카드 안 12–16.

## 공통 틀 (모든 화면)

1. **타이틀바 (44)**: 로고·앱 이름 → 빠른 실행 입력칸(⌘K) → [에이전트 ⌘J] → "실행 4 · 정지 2" → [읽기 전용 스위치] → "15:31 갱신" → 새로고침.
2. **사이드바 (240)**: [개요 (확인 필요 개수)] [활동 기록] → 서버 검색 → 계정별 그룹과 서버 행(상태 점, 이름, 확인 필요 아이콘, CPU%) → 아래 [계정·서버 추가] [설정].
3. **서버 화면 머리**: 즐겨찾기 별, 이름, 상태 배지, 확인 필요 배지, 계정·리전·shape → 오른쪽에 [SSH 열기] [재부팅] [정지] [⋯] → 탭 줄 (개요 / 모니터링 / 컨테이너 n / 파일 / 터미널 n / 로그(준비 중)).
4. **상태 막대 (26)**: SSH 연결 수와 용도(조회·명령·파일·전송), 실시간 상태, 전송 진행, 조회 주기, 버전.

## 화면별 핵심 동작

- **개요**: 요약 4칸, "확인이 필요해요" 목록(디스크 85% 이상, 멈춘 컨테이너, 계정 연결 실패), 서버 카드(상태별 거르기, 여러 대 선택 → 명령 실행·SSH 탭). 정지된 서버는 고를 수 없다.
- **서버 · 개요 탭**: 지금 상태 4칸(누르면 모니터링 탭), 컨테이너 요약과 행 작업, 확인 필요, 정보(공인 IP 가림·복사), 저장된 명령어, 최근 활동.
- **모니터링 탭**: 구간 선택에 "실시간"을 넣어 따로 켜는 버튼을 없앤다. 실시간은 10분 뒤 자동으로 꺼진다(남은 시간 표시). 세 차트가 같은 시점을 가리키고, 알림 기준선과 활동 표시선을 보여준다. 기존 확대 창 기능(휠 확대, 끌어서 이동, 두 번 눌러 처음 범위)은 차트에 그대로 둔다.
- **컨테이너 탭**: 위에 표(행마다 로그·셸·DB 콘솔·재시작·정지/시작), 아래에 로그(컨테이너 전환 칩, 전체/경고/오류, 찾기, 따라가기, 줄 수). 멈춘 컨테이너를 고르면 따라가기가 꺼진다. 로그 아래에 실제로 실행하는 `docker logs` 명령을 보여준다.
- **터미널 탭**: 화면 전체를 바꾸지 않고 탭 안에서 연다. 세션 탭(서버, 서버 › 컨테이너), 오른쪽에 저장된 명령어(이 서버·모든 서버 구분)와 여러 서버에서 실행. 결과는 서버별 성공·실패로 그 자리에 보인다.
- **파일 탭**: 2창 + 자주 가는 경로 + 선택 작업 막대 + 편집 중 표시 + 아래 전송 목록. 지금 `SftpDialog`의 규칙(같은 이름 처리, 삭제 확인, 소유자 경고, 편집 감시)은 그대로 둔다.
- **설정**: 일반 / 알림 / 보안·안전 / 연결·조회 / 에이전트 / 업데이트·정보. 연결·조회에 "지금 열린 SSH 연결" 표(서버 × 용도). 에이전트 항목은 에이전트를 만들 때까지 숨긴다.

## 새로 필요한 것 (화면 작업에서 바로 만들지 않고 먼저 상의)

- **읽기 전용 모드**: 정지·재부팅·삭제·덮어쓰기·일괄 실행을 막는 앱 전체 상태.
- **활동 기록 저장소**: 이 PC에만, 30일, 명령 출력·비밀값·공인 IP는 남기지 않는다.
- **개요의 디스크 사용량**: 실행 중인 서버 전부를 조회용 연결로 주기적으로 읽어야 한다. 5분 이상 간격.
- **알림 규칙 추가**: 디스크 기준, 컨테이너 멈춤.
- **에이전트**: 명령 분류(읽기·변경·위험·알 수 없음), 허용 흐름, 출력 자르기·가리기, 모델 연결. 시안 `AgentDock`, `AgentCases`, `Settings`의 에이전트 항목 참고.

## 구현 순서 (화면 하나 = 브랜치 하나)

1. 토큰·공통 부품 (`Theme` 값 갱신, 배지·칩·구간 선택·스위치·막대)
2. 공통 틀: 서버 화면 머리 + 탭 구조 + 상태 막대
3. 컨테이너 탭 → 4. 모니터링 탭 → 5. 파일 탭 → 6. 터미널 탭 → 7. 서버 · 개요 탭
8. 설정 (에이전트 항목 제외)
9. 개요 (디스크 조회 상의 후) → 10. 빠른 실행 → 11. 활동 기록 (저장소 상의 후)
12. 에이전트 (별도 설계 후)

각 단계에서 `./gradlew snapshot`으로 찍은 화면과 `images/`의 이미지를 비교한다. 같게 만들 수 없는 부분은 이유를 적어 보고한다.
